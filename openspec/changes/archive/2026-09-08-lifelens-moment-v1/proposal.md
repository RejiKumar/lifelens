# Proposal: lifelens-moment-v1 — Proactive Actionable Insight (the "Moment")

## Why

Today LifeLens answers the question the user asks, but it never tells the user *what matters*. A user who points the camera at a leak under the sink, a scratched wire, or a medication bottle gets identification fields (`title`, `summary`, `observations`) but no prioritized "so what do I do now?" callout. The product promise is **Point → Understand → Act**, yet the "Act" step is buried. lifelens-moment-v1 makes the primary output of a scan an actionable [**Moment**](https://en.wikipedia.org/wiki/Moment_(physics)) — one prioritized, image-grounded insight — surfaced above the identification result, without any extra round-trip or user effort.

## What Changes

- **Backend — `moment` in the analysis result**: the synchronous `POST /scan/analyze` response's `AnalysisResult` gains a `moment` block (one prioritized `headline` = "*why it matters*", plus `action` = "*what to do*"). It is produced by the **same single AI call** — no new endpoint, no polling, no added latency budget.
- **Backend — AI pipeline extension**: provider protocol input/output extended so the structured AI response includes the moment; provider prompt engineered to require one grounded, conservative, actionable moment; provider stub returns a deterministic moment; normalization/clamping and validation extended; moment persisted with the analysis row.
- **Backend — Persistence**: `analyses` table gains moment columns (migration). Full historical result shape stays intact for `GET /scan/{id}`.
- **Mobile — Leading insight UI**: the analysis result screen surfaces the moment as a **prominent leading card above the identification result** (above risk badge/title), presenting headline + action. Safety communication (risk badge, safety banner, warnings) remains unchanged and prominent; high-risk output still leads with safety.
- **Tests**: backend pytest for schema/normalizer/repository/persistence of the moment and stub determinism; mobile Jest + RNTL for moment rendering and placement on the result screen.

## Capabilities

### New Capabilities

- `ai-moment`: the proactive, prioritized actionable insight. Defines what a Moment is (one image-grounded headline + one action), where it is surfaced (leading, above the identification result), its constraints (earned from the same single analysis call; grounded in the image; conservative on high-risk subjects; never a diagnosis or a substitute for professional help), and how it differs from the identification fields.

### Modified Capabilities

- `ai-analysis`: `AnalysisResult` is extended with a `moment` field; the structured-output schema, prompt, validation/normalization sequence, and persistence contract change accordingly. `moment` SHALL be present and valid on every completed analysis.

## Impact

- **Backend** (`backend/`): `app/schemas/scan.py` (new `Moment` schema + `AnalysisResult.moment`), `app/providers/base.py` (`RawAnalysis.moment` + provider error taxonomy), `app/providers/gemini.py` (production Gemini provider, structured JSON output incl. moment), `app/providers/stub.py` (deterministic moment for QA/tests), `app/services/analysis.py` (coerce/normalize/validate moment + provider error mapping), `app/models/scan.py` + Alembic migration (moment columns on `analyses`), `app/repositories/scan.py` (`AnalysisRecord` + row mapping), `app/api/deps.py` (provider selection), `app/core/config.py` (AI provider settings). No new API routes; secrets stay backend-only.
- **Mobile** (`mobile/`): `src/features/scan/domain/types.ts` (`Moment` + `AnalysisResult.moment`), `src/app/analysis/[id].tsx` (leading-insight card above the risk badge), related jest/RNTL tests.
- **Contracts**: `POST /scan/analyze` and `GET /scan/{id}` responses include `analysis.moment` with `headline` and `action`. No new API routes; no mobile→AI path introduced (AI stays backend-only).
- **Out of scope (not implemented)**: moment personalization/memory, deep-linking to a moment, follow-up chat laundering through the moment, moment-specific analytics events.
- **Production AI (in scope by product decision)**: the production Moment is generated by the real Gemini provider, returned in the same structured AI call as identification + safety metadata (`AI_PROVIDER=gemini` default; the deterministic stub is pinned for local QA and tests only, never production).

### A note on the name

The working title "Moment" (as in a small but decisive change of momentum) is a codename; it may be renamed to user-facing copy (e.g. "Your insight" / "What to do") in the same change without renegotiating this proposal.
